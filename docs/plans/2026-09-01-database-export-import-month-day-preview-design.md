# Дизайн: Экспорт и импорт базы данных, редактирование по `r`, всплывающее меню дня в месяце по `o`

## 1. Контекст и цели

1. **Экспорт и импорт базы данных (`--export` / `--import`):**
   - Возможность выгрузить актуальное состояние расписания из базы SQLite в отдельный переносимый `.db` файл.
   - Возможность безопасно применить этот файл на другом компьютере (ноутбуке) одной командой, с валидацией целостности данных, интерактивным подтверждением и автосозданием резервной копии старой базы.
2. **Редактирование по `r` (включая AGENDA):**
   - Добавить клавишу `r` (от «Редактировать») как алиас к `e` (`Action::Edit`) во всех режимах календаря и внутри оверлея Agenda.
   - Перенести циклический фильтр типа элементов в Agenda (`ItemType`) на клавишу `R` (`Shift+R`).
3. **Контекстное меню событий дня в режиме Месяца по `o`:**
   - В режиме `Month` при нажатии `o` на выбранном дне отображать выпадающее/всплывающее меню дел этого дня под соответствующей ячейкой сетки.
   - Предоставить навигацию клавишами `j` / `k`, открытие по `Enter` и моментальное редактирование по `r` / `e`. Закрытие по `Esc` / `o`.

## 2. Архитектурные решения и компоненты

### 2.1. Хранилище и CLI (`src/storage`, `src/cli`, `src/main.rs`)
- **Экспорт (`Database::export`):**
  - Метод в `Database` принимает целевой путь `&Path`.
  - Вызывает SQLite команду `VACUUM INTO ?1`. Это обеспечивает создание чистого, неделимого, дефрагментированного файла без блокировок и без необходимости сбрасывать WAL-файлы вручную.
  - Подсчитывает количество экспортированных событий и размер полученного файла для красивого отчета в CLI.
- **Импорт (`Database::import_file` / `cli::run_import`):**
  - Шаг 1: Проверка существования файла и доступности на чтение.
  - Шаг 2: Валидация через rusqlite в режиме read-only: `PRAGMA integrity_check`, проверка наличия таблиц `events`, `schema_migrations`, `tags`. При ошибке вывод сообщения и немедленный выход с ненулевым кодом.
  - Шаг 3: Запрос подтверждения `Заменить базу данных? [y/N]` (пропускается, если передан флаг `--force` / `-f`).
  - Шаг 4: Резервное копирование текущего `calendar.db` в `calendar.db.bak.YYYYMMDD_HHMMSS`.
  - Шаг 5: Атомарная замена файла базы данных целевым файлом, удаление устаревших `-wal` и `-shm` файлов.
  - Шаг 6: Открытие новой базы через `Database::open` и прогон миграций (на случай импорта базы от более ранней версии).
- **Парсер CLI (`src/cli/mod.rs`):**
  - Поддержка `rutendar --export [путь]` / `-e` / `export`.
  - Поддержка `rutendar --import <путь> [--force / -f]` / `-i` / `import`.

### 2.2. Горячие клавиши (`src/input/keymap.rs`, `src/app/action.rs`)
- В `Keymap::normal`:
  - `KeyCode::Char('r')` мапится в `Action::Edit` (как и `'e'`).
  - `KeyCode::Char('R')` мапится в `Action::CycleItemType`.
  - В `View::Month` при нажатии `'o'` генерируется `Action::OpenMonthDay` (или переключение режима предпросмотра дня).
- В `src/app/update/mod.rs`:
  - В оверлее `Agenda` действие `Action::Edit` обрабатывает как `'e'`, так и `'r'`.

### 2.3. Всплывающее меню дня в Месяце (`src/app`, `src/ui/month.rs`, `src/ui/popup.rs`)
- **Состояние (`AppState` / `Popup::MonthDayPreview`):**
  - Новое состояние всплывающего окна `Popup::MonthDayPreview { date: NaiveDate, selected: usize }` или прямое поле в `AppState`.
  - При активном попапе:
    - `j` / `Down` — следующий пункт.
    - `k` / `Up` — предыдущий пункт.
    - `Enter` — открыть дело (переход в Day view с выбором события и открытие его деталей).
    - `r` / `e` — открыть редактирование выбранного события (`Action::Edit`).
    - `Esc` / `o` — закрыть окно.
- **Отрисовка (`src/ui/month.rs`):**
  - Расчет абсолютных координат ячейки дня в сетке `columns[day]`.
  - Позиционирование всплывающего блока:
    - X: левый край ячейки дня (с выравниванием, чтобы блок шириной ~32-40 символов не выходил за правый край экрана).
    - Y: под ячейкой дня (`cell.y + cell.height`). Если ячейка расположена на 5-6 неделе месяца и не помещается снизу, блок рисуется над ячейкой (`cell.y.saturating_sub(height)`).
  - Отрисовка списка дел дня с временными интервалами, маркерами важности `!`, цикличностью `↻` и заголовками.

## 3. План верификации
1. Unit-тесты для экспорта: выгрузка во временный файл, проверка корректности структуры через `PRAGMA integrity_check`.
2. Unit-тесты для импорта: проверка валидации битого файла, создание бэкапа, успешная загрузка событий.
3. Тесты маппинга клавиш: `r` в календаре и в Agenda вызывает `Action::Edit`, `R` переключает фильтр.
4. Тестирование логики навигации по дню в режиме Месяца.
5. Запуск `cargo check`, `cargo test`, `cargo clippy`.
